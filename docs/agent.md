# FoodWise — Agent Guide

This document describes how FoodWise was designed and built by an AI coding agent, how to continue development, and the conventions to follow.

---

## Project Origin

FoodWise was generated by **Antigravity** (Google DeepMind Advanced Agentic Coding) in response to the following spec:

> Small restaurants waste food because they can't efficiently track inventory or alert customers about surplus. FoodWise lets restaurants manage menus, track real-time inventory, accept orders, and push surplus alerts to subscribed customers before stock expires.

## Architecture Decisions

### 1. Bearer Token Only (no cookies)
Tokens are stored in React memory (`useState`). Not `localStorage` (XSS risk) or `sessionStorage`. Cleared on logout or page refresh.

### 2. JWT Validation via auth-service
Services (`catalog-order-service`, `inventory-app`) do NOT parse JWTs locally. They call `GET /auth/validate` on auth-service. This means:
- Token revocation is respected immediately
- No secret key leakage outside auth-service
- Results are cached in Redis for 30s to reduce load

### 3. Two Maven Modules for Inventory
`inventory-notification-service` contains two independent modules:
- `inventory-app` — REST API service (port 8083)
- `notification-worker` — Background poller (no HTTP endpoints)

This produces **two Docker images** — the canonical multi-container pod pattern for K8s.

### 4. Shared INTERNAL_SERVICE_TOKEN
For Docker Compose dev, services authenticate internal calls (deduct/restore) with a shared env var token.

### 5. Surplus Detection
Dual-trigger:
- Real-time: checked after every stock change in `InventoryService`
- Scheduled: `SurplusDetectionService` scans all items every hour (catches expiry without stock changes)

## How to Extend

### Adding a new endpoint to catalog-order-service

1. Add DTO in `com.foodwise.catalog.dto`
2. Add repository method if needed
3. Add service method in `MenuService` or `OrderService` with RBAC check
4. Add controller endpoint in `MenuController` or `OrderController`
5. Add Bean Validation annotations on the DTO
6. The `JwtAuthenticationFilter` auto-populates the `ValidateResponse` principal — use `(ValidateResponse) authentication.getPrincipal()` in controllers

### Adding a new role

1. Add role to `V2__seed_roles.sql` in auth-service
2. Add `@PreAuthorize("hasRole('NEW_ROLE')")` in controller methods
3. Update `AuthContext.jsx` to handle new role checks

### Switching from shared token to mTLS

In `inventory-app/SecurityConfig.java`, the `InternalTokenFilter` guards `/inventory/deduct` and `/inventory/restore`. When deploying with Istio:
1. Remove `InternalTokenFilter` from the security chain
2. Configure `PeerAuthentication` and `AuthorizationPolicy` in your Istio manifests
3. Remove `INTERNAL_SERVICE_TOKEN` env var from all services

## Security Checklist (before production)

- [ ] Replace `JWT_SECRET` with a 256-bit random secret from a secret manager
- [ ] Replace `INTERNAL_SERVICE_TOKEN` with Istio mTLS
- [ ] Add OAuth2/OIDC provider (Google, GitHub) to auth-service
- [ ] Enable HTTPS — configure TLS termination at load balancer or Istio ingress
- [ ] Replace Mailhog with real SMTP (AWS SES, SendGrid)
- [ ] Set up log aggregation (ELK, Loki)
- [ ] Enable `spring-boot-starter-actuator` metrics → Prometheus/Grafana
- [ ] Run `mvn dependency:check` for CVE scanning
- [ ] Set PostgreSQL connection passwords via Kubernetes Secrets
- [ ] Configure HPA (Horizontal Pod Autoscaler) for catalog-order-service

## File Naming Conventions

- Java: PascalCase for classes, camelCase for methods/fields
- SQL: `snake_case` for table and column names, `UPPER_CASE` for SQL keywords
- React: PascalCase for components, camelCase for hooks/utilities
- CSS: BEM-style class names (`.card__header`, `.btn-primary`)
- Environment variables: `SERVICE_COMPONENT_SETTING` (e.g., `AUTH_POSTGRES_PASSWORD`)
